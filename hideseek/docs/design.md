# 학교 변신 숨바꼭질 — 설계 문서

작성일: 2026-11-02 · 상태: 검토 대기

## 1. 목적과 사용 상황

- **대상**: 초등 6학년 우리 반 학생 7명, 교사 1명
- **기기**: 크롬북(브라우저), 같은 교실에서 동시에 접속
- **시간**: 40분 수업 한 차시 안에서 여러 판(6~7판)을 반복
- **성격**: 놀이용(학습 요소 없음). 채팅은 넣지 않음 — 같은 교실이므로 말로 소통한다.
- **교사 역할**: 플레이하지 않고 진행만 맡는다(방 만들기, 판 시작, 관전, 점수판).

### 성공 기준

1. 학생 7명과 교사 1명이 크롬북에서 끊김 없이 동시에 접속·이동한다.
2. 한 판이 끝나면 교사가 버튼 하나로 다음 판을 시작하고, 술래는 자동으로 교체된다.
3. 6학년 학생이 1분 설명을 듣고 바로 플레이할 수 있다.
4. 40분 동안 누적 점수가 유지되고, 마지막에 최종 순위를 보여줄 수 있다.

## 2. 게임 규칙

### 2.1 접속

1. 교사: 사이트 접속 → "선생님" → 교사 코드(`VITE_TEACHER_CODE`) 입력 → 4자리 방 코드 생성.
2. 학생: 방 코드 + 이름(1~8자) 입력 → 대기실 입장.
3. 방 정원은 학생 7명. 정원 초과 시 입장 거부.
4. 판이 진행 중일 때 들어온 학생은 다음 판부터 참여(그 판은 관전 대기).
5. 교사는 이름을 보고 학생을 내보낼 수 있다. 내보낸 학생은 같은 방에 다시 들어올 수 없다.

### 2.2 편

- **술래 편**: 그 판의 술래 1명 + 잡힌 학생들. 사람 모습으로 다닌다.
- **숨는 편**: 나머지 6명. 학교 사물로 변신한다.
- 술래는 입장 순서대로 돌아간다. 판이 끝날 때마다 다음 학생이 술래가 된다. 접속이 끊긴 학생은 건너뛴다.

### 2.3 한 판의 단계

| 단계 | 시간 | 술래 | 숨는 편 |
|---|---|---|---|
| 준비 | 30초 | 화면 가림("30까지 세는 중"), 이동 불가, 고정 시작 위치 | 변신할 사물을 고르고 원하는 곳으로 이동 |
| 찾기 | 최대 4분 | 시야 반경 안만 보임, 이동하며 사물 클릭으로 확인 | 변신 상태로 이동 가능(아래 '흔들림' 참고) |
| 결과 | 15초 | 숨은 사람 공개, 이번 판 점수 표시 | 같음 |

- 숨는 편이 모두 잡히면 찾기 단계가 즉시 끝난다.
- 결과 단계가 끝나면 대기실로 돌아가고, 교사가 "다음 판"을 누르면 새 판이 시작된다.

### 2.4 잡기

- 술래 편은 시야 안의 사물을 클릭해 확인한다. 클릭 대상은 원래 놓인 사물 또는 변신한 학생이다.
- 클릭한 대상과 술래 편 학생의 거리가 **확인 거리(120px)** 이내여야 유효하다. 멀면 아무 일도 없다(벌칙 없음, "더 가까이 가세요" 안내).
- **변신한 학생을 클릭** → 잡힘. 잡힌 학생은 술래 편이 되어 그 자리에서 사람 모습으로 바뀌고, 바로 함께 찾는다.
- **원래 사물을 클릭** → 헛짚음. 그 술래 편 학생은 **2초간 정지**(이동·클릭 불가).
- 정지 중인 학생의 클릭 요청은 심판이 무시한다.

### 2.5 이동과 흔들림

- 이동: 방향키 또는 WASD. 확인: 마우스/터치패드 클릭.
- 이동 속도: 모두 140px/초.
- 변신한 학생이 **움직이는 동안** 술래 편 화면에서 그 사물이 좌우로 살짝 흔들려 보인다. 멈추면 흔들림이 사라진다.
- 숨는 편 본인 화면과 같은 숨는 편 화면에는 흔들림이 보이지 않는다. 교사 화면에서는 보인다.

### 2.6 시야

- 술래 편 화면: 자기 위치 반경 **180px**만 밝게 보이고 나머지는 어둡다. 벽 그림자는 처리하지 않는다(단순 원형 시야).
- 숨는 편 화면: 맵 전체가 보인다.
- 교사 화면: 맵 전체 + 변신한 학생 위에 이름표.

### 2.7 점수(40분 누적)

| 대상 | 조건 | 점수 |
|---|---|---|
| 숨는 편 | 찾기 단계에서 30초 버틸 때마다 | +1 |
| 숨는 편 | 찾기 단계 끝까지 살아남음 | +5 |
| 술래 편 | 숨은 학생 1명 잡을 때마다(처음 술래·잡혀서 합류한 학생 모두) | +3 |

- 승패 표시: 4분 안에 모두 찾으면 "술래 편 승리", 한 명이라도 남으면 "숨는 편 승리". 승패 자체에는 추가 점수가 없다.

### 2.8 맵과 사물

- 위에서 내려다보는 학교 한 층: 교실 2개 + 복도 + 도서관. 크기 약 1600×960px(32px 타일).
- 원래 놓인 사물 50~60개.
- 변신 가능한 사물 10~12종: 책상, 의자, 사물함, 화분, 쓰레기통, 책장, 지구본, 우산꽂이, 소화기, 청소도구함, 책 더미, 정수기 등.
- 첫 버전 그림은 단순 도형 + 이모지 수준. 재미가 확인되면 다듬는다.

## 3. 교사 화면

- 방 코드 크게 표시, 접속 학생 목록(접속 상태 표시)
- 버튼: **판 시작/다음 판**, **일시정지/재개**, **판 강제 종료**, **학생 내보내기**, **최종 순위**
- 전체 맵 관전(이름표 포함) — 교실 TV에 띄우는 용도
- 누적 점수판(오른쪽 고정)
- 최종 순위: 1~3등 시상 화면

일시정지 중에는 모든 학생의 이동·클릭이 막히고 타이머가 멈춘다. 강제 종료하면 그 시점 기준으로 점수를 정산하고 결과 단계로 간다.

## 4. 구조

### 4.1 기술

- Phaser 3 + Vite + TypeScript (기존 `mumusubject`와 동일)
- Firebase Realtime Database + 익명 로그인 — `mumusubject`와 **같은 Firebase 프로젝트** 사용
- 배포: Vercel 정적 배포(Root Directory: `hideseek/client`)
- 서버 없음: **교사 브라우저가 심판(referee)** 역할

### 4.2 폴더

```
hideseek/
  docs/design.md            # 이 문서
  database.rules.json       # Realtime DB 보안 규칙
  client/
    src/
      game/rules.ts         # 순수 규칙 함수(잡기 판정, 점수, 술래 순서, 단계 전환)
      game/map.ts           # 벽, 원래 사물 목록, 변신 가능 사물 종류
      net/firebase.ts       # Firebase 초기화, 익명 로그인
      net/room.ts           # 방 생성·입장, 위치 업로드, 구독 (Firebase 호출은 여기만)
      host/referee.ts       # 교사 브라우저의 심판: 타이머, 잡기 요청 처리, 점수 반영
      scenes/               # 입장, 대기실, 학생 게임, 교사 관전, 결과·시상
```

`rules.ts`는 Firebase·Phaser에 의존하지 않는다. `referee.ts`는 `rules.ts`를 호출하고 결과를 `room.ts`로 쓴다.

### 4.3 데이터 구조

```
rooms/{code}/
  meta                       # 교사만 씀
    hostUid
    phase: 'lobby' | 'prep' | 'seek' | 'result' | 'final'
    round
    phaseEndsAt              # 서버 시간 기준 ms
    paused, remainingMs      # 일시정지 시 남은 시간 보관
    seekerOrder: uid[]       # 입장 순서
  players/{uid}
    profile                  # 학생 본인이 씀: name, prop(고른 사물 종류), joinedAt
    state                    # 교사만 씀: team('seek'|'hide'|'wait'), caught, frozenUntil, score
  presence/{uid}             # 학생 본인이 씀: online(onDisconnect로 false)
  pos/{uid}                  # 학생 본인이 씀: x, y, moving (초당 약 10회)
  actions/{pushId}           # 학생이 추가: { uid, targetType: 'decor'|'player', targetId, at }
  kicked/{uid}               # 교사만 씀
```

### 4.4 잡기 처리 흐름

1. 술래 편 학생이 사물을 클릭 → `actions`에 요청 추가.
2. 교사 브라우저의 심판이 `actions`를 구독해 순서대로 처리:
   - 요청자가 술래 편이 아니거나, 정지 중이거나, 찾기 단계가 아니면 무시.
   - 요청자의 `pos`와 대상 위치의 거리가 120px을 넘으면 무시.
   - 대상이 살아 있는 숨는 편 학생이면 → 잡힘 처리(대상 `team='seek'`, `caught=true`, 요청자 +3점).
   - 대상이 원래 사물이면 → 요청자 `frozenUntil = now + 2000`.
3. 처리한 요청은 삭제. 모든 화면은 `state`를 구독해 갱신.

### 4.5 보안 규칙 요약

- `meta`, `players/*/state`, `kicked`: `auth.uid == meta.hostUid`만 쓰기 가능.
- `players/{uid}/profile`, `presence/{uid}`, `pos/{uid}`: `auth.uid == uid`만 쓰기 가능, 그리고 `kicked/{uid}`가 없어야 함.
- `actions`: 방에 등록된 학생만 추가 가능, 교사만 삭제 가능.
- 기존 `mumusubject`의 Firestore 규칙과는 별개라 서로 영향 없음.

### 4.6 알려진 한계(받아들임)

- 학생 브라우저에도 전체 데이터가 내려온다. 개발자도구를 열면 누가 무엇으로 변신했는지 볼 수 있다. 화면에는 표시하지 않는다.
- 교사 코드는 `mumusubject`와 같이 클라이언트 번들에 들어간다. 교실 내부용으로 충분하다고 본다.

## 5. 끊김 대처

| 상황 | 처리 |
|---|---|
| 학생 일시 끊김 | `presence` onDisconnect로 오프라인 표시. 익명 uid가 브라우저에 남아 새로고침 시 같은 편·점수로 복귀 |
| 끊긴 숨는 편 | 그 자리에 사물로 남음. 잡히면 정상 처리 |
| 술래 차례 학생이 끊김 | 판 시작 시 다음 순서의 접속 중인 학생을 술래로 지정 |
| 교사 탭 닫힘 | 심판이 없으므로 학생 화면에 "선생님 기다리는 중" 표시. 교사가 같은 브라우저로 다시 열면 같은 `hostUid`로 방에 복귀하고, 남은 시간부터 이어서 진행(교사 이탈 감지 시 `paused`로 전환) |
| 기기 시계 차이 | `phaseEndsAt`을 Firebase 서버 시간 기준으로 저장하고, 각 화면은 `.info/serverTimeOffset`으로 보정 |

## 6. 테스트

1. **단위 테스트(Vitest)** — `rules.ts`
   - 잡기 판정: 거리 안/밖, 이미 잡힌 대상, 정지 중 요청자, 찾기 단계 외 요청
   - 헛짚음 2초 정지
   - 점수: 30초당 +1, 생존 +5, 잡기 +3
   - 술래 순서 순환, 끊긴 학생 건너뛰기
   - 단계 전환, 전원 잡힘 시 조기 종료
2. **통합 테스트(Firebase 에뮬레이터 + Playwright)**
   - 브라우저 8개(교사 1 + 학생 7)로 방 입장 → 판 시작 → 잡기 → 결과 → 다음 판 술래 교체 확인
   - 보안 규칙: 학생이 `state`/`meta`에 쓰기 시도 시 거부 확인
3. **현장 확인(선생님)**
   - 배포 후 학교 와이파이에서 크롬북 2~3대로 접속, Firebase 접속 차단 여부와 움직임 부드러움 확인

## 7. 준비물(선생님이 Firebase 콘솔에서 할 일)

1. 기존 `mumusubject` 프로젝트에서 **Realtime Database** 만들기(지역: asia-southeast1).
2. **Authentication → 익명 로그인** 사용 설정.
3. `database.rules.json` 내용을 Realtime Database → 규칙 탭에 게시.
4. Vercel 새 프로젝트 환경변수: 기존 `VITE_FIREBASE_*` + `VITE_FIREBASE_DATABASE_URL` + `VITE_TEACHER_CODE`.

## 8. 첫 버전에서 뺀 것

판 설정 변경(시간·판 길이), 맵 여러 개, 채팅, 효과음, 정교한 그래픽, 벽에 가리는 시야.
